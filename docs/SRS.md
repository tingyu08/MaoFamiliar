# Familiar 軟體需求規格（SRS）

| 項目 | 內容 |
|---|---|
| 文件版本 | v0.3（草稿）：加入第 0 週驗證結果、依工作分工、Decisions 選候選 |
| 日期 | 2026-11-23 |
| 相關文件 | [PRD.md](PRD.md)、[SDD.md](SDD.md) |

需求等級：**Must**（該階段必須）、**Should**（盡量）、**Could**（有空再做）。
階段：P1 核心＋網頁、P2 通用桌面＋知識庫、P3 即時模式、P4 排程通知（見 PRD 4.1）。

---

## 1. 名詞定義

| 名詞 | 定義 |
|---|---|
| 目標（Target） | AI 要操作的對象：一個網站（以網域識別），或一個桌面應用程式／遊戲（以執行檔名稱識別） |
| 任務（Task） | 對某個目標的一次請求，內容是一句話描述的目的 |
| 步驟（Step） | 任務中的一個動作 |
| 執行器（Executor） | 實際執行動作的元件，有瀏覽器（Playwright）和桌面（Windows 輸入）兩種 |
| 動作後端（Action backend） | 讓模型輸出動作的方式。`native_cu` 使用 Gemini 內建的 Computer Use 工具；`custom_fc` 使用我們自己定義的動作函式 |
| 知識庫（Knowledge base） | 每個目標各一份，記錄學到的畫面狀態、技能、操作心得。全部是資料，不是程式 |
| 畫面狀態（State） | 一種可辨識的畫面，例如「主選單」「戰鬥中」「獎勵彈窗」，包含名稱、描述和參考截圖 |
| 技能（Skill） | 一段錄製下來、可以重播的動作序列，例如「領取每日獎勵」 |
| 心得（Note） | 一段文字知識，例如「按 Esc 可以關閉彈窗」，由 AI 或使用者寫入 |
| 操作模式 | `ui` 模式：絕對座標點擊，給選單式介面用；`realtime` 模式：按住按鍵、相對滑鼠、動作區塊，給即時遊戲用 |
| 模型退階鏈 | 依序嘗試的模型清單；某個模型的配額用完時，就改用下一個 |

## 2. 功能需求

### 2.1 任務管理

| 編號 | 需求 | 等級 | 階段 |
|---|---|---|---|
| FR-001 | 使用者應能建立任務：目標（網址，或從清單中選擇視窗）加上任務描述（1–2000 字） | Must | P1/P2 |
| FR-002 | 網址只接受 http(s) 協定；拒絕 `file:`、`javascript:`、`chrome:` 等協定 | Must | P1 |
| FR-003 | 系統應列出目前所有可見的頂層視窗，包含標題、執行檔名稱與縮圖，供使用者選擇 | Must | P2 |
| FR-004 | 同一時間只允許一個任務執行 | Must | P1 |
| FR-005 | 使用者應能隨時停止任務；系統應在 2 秒內停止，並放開所有按住的按鍵與滑鼠鍵 | Must | P1 |
| FR-006 | 任務狀態應為以下其中一種：`pending`、`running`、`waiting_user`、`waiting_quota`、`succeeded`、`failed`、`stopped` | Must | P1 |
| FR-007 | 任務結束時應記錄：結果文字、步數、耗時、各模型的呼叫次數與 token 數、各層的命中次數 | Must | P1 |
| FR-008 | 系統應提供任務歷史，以及單一任務的步驟回放 | Should | P1 |

### 2.2 代理人迴圈

| 編號 | 需求 | 等級 | 階段 |
|---|---|---|---|
| FR-101 | 代理人迴圈應同時支援 `native_cu` 和 `custom_fc` 兩種動作後端，可在設定檔中切換，也可以每個模型分別設定；**預設為 `custom_fc`**（第 0 週驗證：原生 `computer_use` 會隨機被安全分類器以 400 擋下） | Must | P1 |
| FR-101a | 使用 `native_cu` 時若收到 400 安全封鎖，同一步應自動改用 `custom_fc` 重送一次 | Should | P1 |
| FR-102 | `custom_fc` 後端應以一般函式宣告提供動作集（見 SDD 4.2），並透過 Interactions API 呼叫，不依賴 `computer_use` 工具 | Must | P1 |
| FR-103 | 兩種後端的座標都採用正規化的 1000×1000 座標系，系統負責換算成目標的實際像素 | Must | P1 |
| FR-104 | 每一步回傳給模型的內容應包含：最新截圖、目前網址或視窗標題、上一步的執行結果或錯誤、相關的知識庫心得 | Must | P1 |
| FR-105 | 模型沒有呼叫任何函式，或呼叫 `task_done(summary)` 時，視為任務完成 | Must | P1 |
| FR-106 | 每個任務應有步數上限（預設 80）與時間上限（預設 30 分鐘） | Must | P1 |
| FR-107 | 動作失敗時，應把錯誤和新截圖回傳給模型，不要中止任務 | Must | P1 |
| FR-108 | 連續多步截圖幾乎相同（感知雜湊比對）時，應判定為卡住：第 5 步提醒模型，第 8 步停止任務 | Should | P1 |
| FR-108a | 代理人連續 4 次做一模一樣的動作（種類與參數都相同）時，應提醒模型「已重複 N 次，請看畫面提示、換做法」。畫面一直有小變化（例如遊戲動畫）時 FR-108 抓不到這種卡住（2026-11-24 加入：遊戲試跑時模型無視「↑ JUMP」提示，連按 30 次右鍵） | Should | P1 |
| FR-109 | 應提供 `ask_user(reason)` 函式，讓 AI 暫停任務，請使用者協助 | Must | P1 |
| FR-110 | 瀏覽器目標應提供 `click_element(ref)`、`fill_element(ref, text)` 函式（混合定位） | Should | P1 |
| FR-110a | 元素表建立後，網站重新渲染換掉節點、使 `ref` 失效時：用快照時的 role＋名稱＋是否為密碼欄找回**唯一**相符的可見元素再操作；找不到或有多個相符時立刻回報「頁面已更新」，不等滿元素逾時（2026-11-26 加入：真實網站試跑時，維基百科聚焦搜尋框後換成動態元件，第 3 層點「搜索」空等 5 秒後失敗） | Should | P1 |
| FR-111 | 模型支援時，應開啟 `enable_prompt_injection_detection` | Must | P1 |
| FR-113 | 應提供 `zoom(x1, y1, x2, y2)`：重新截圖、裁出指定區域並放大到長邊 1024px，連同目前的完整截圖回傳給模型；只看不操作，不經安全確認、不計入卡住偵測、不錄進技能。系統指示要求模型在答案依賴小字、數字或小圖示時先放大再回答（2026-11-26 加入：真實網站試跑時，模型把書單的 4 顆星看成 5 顆星，回報錯誤答案卻被判定成功） | Should | P1 |
| FR-112 | 對話紀錄超過設定長度（預設 20 步）時，應把較早的步驟壓縮成文字摘要，只保留最近 3 張截圖 | Must | P1 |

### 2.3 模型與配額管理

| 編號 | 需求 | 等級 | 階段 |
|---|---|---|---|
| FR-201 | 模型**依工作分工**，每種工作各有一條退階鏈，由設定檔定義。預設：**操作**（每一步的點擊、按鍵、對話壓縮）用 `gemini-3.5-flash-lite` → `gemini-3.6-flash` → `gemini-3.8-flash`；**規劃**（拆子目標、卡住時反思、整理心得）用 `gemini-4-hydrogen` → `gemini-3.8-flash` → `gemini-3.6-flash` → `gemini-3.5-flash-lite`；**判斷**（畫面狀態、風險、是否完成）用 `gemini-decision-1` | Must | P1 |
| FR-201a | 同一個模型出現在多條鏈時，配額只算一份（共用計數） | Must | P1 |
| FR-201b | 規劃鏈全部不可用時，規劃工作改用操作鏈的模型，任務不中斷 | Must | P1 |
| FR-202 | 系統應在本機記錄每個模型每分鐘與每天的請求數、token 數；每日用量在太平洋時間午夜歸零 | Must | P1 |
| FR-203 | 每個模型的 RPM、TPM、RPD 上限寫在設定檔中（由使用者從 AI Studio 控制台抄錄）；送出請求前先檢查，快超過每分鐘上限時主動等待 | Must | P1 |
| FR-204 | 收到 429 `RESOURCE_EXHAUSTED`，或本機紀錄顯示當日配額已用完時，應把該模型標記為「今日用完」，並改用鏈中的下一個模型 | Must | P1 |
| FR-204a | 收到 503（模型過載）、其他伺服器錯誤或逾時時：**鏈上還有其他可用模型**，同一模型只重試 1 次（間隔 5 秒）就換模型；**已經是最後一個可用模型**，才退避重試 3 次（10、20、40 秒）。仍失敗就把該模型「暫時停用」：第一次 60 秒，同一模型連續過載依序加倍（2、4、8 分鐘），上限 10 分鐘；呼叫成功或換日後重新從 60 秒起算。冷卻結束後優先回到較前面的模型。（2026-11-24 依兩次冒煙測試調整：原本一律重試 3 次會空等約 70 秒；固定冷卻 10 分鐘則會在所有模型同時過載時讓任務等滿 10 分鐘）。以上數字都可在 `config.yaml` 調整；目前預設依使用者要求改為「全速」：不重試、不退避，冷卻固定 3 秒 | Must | P1 |
| FR-205 | 換模型時，應保留任務進度：把目前的步驟摘要交給新模型，從頭開始一段新的對話 | Must | P1 |
| FR-206 | 整條鏈都用完時，任務轉為 `waiting_quota`，前端顯示預計恢復時間；使用者可以選擇等待或停止 | Must | P1 |
| FR-207 | 前端應即時顯示每種工作目前使用的模型、各模型今日剩餘的估計額度 | Must | P1 |
| FR-207a | 收到 429 時，應解析錯誤訊息中的「retry in XmYs」作為該模型的恢復時間 | Should | P1 |
| FR-208 | 系統只使用免費額度的 API key；不得自動切換到付費方案 | Must | P1 |
| FR-209 | Decisions API（`gemini-decision-1`）也納入配額管理（免費版：200 RPM、**每分鐘 50,000 輸入 token**、10,000 RPD）；以回應中的 `usage` 累計每分鐘 token，快超過時主動等待 | Must | P1 |

### 2.4 安全

| 編號 | 需求 | 等級 | 階段 |
|---|---|---|---|
| FR-301 | 使用 `native_cu` 時，若 `safety_decision.decision == "require_confirmation"`，應暫停並請使用者確認；同意後在結果中帶入 `safety_acknowledgement: true` | Must | P1 |
| FR-302 | 使用 `custom_fc` 時，每個會造成影響的動作都要附上 `risk` 參數（`low` / `high`），由模型自行評估；`high` 一律需要使用者確認 | Must | P1 |
| FR-303 | 使用 `custom_fc` 時，點擊前應以 Decisions API 的 `noul` 問題，檢查「這個點擊是否會造成付款、送出、刪除，或其他無法復原的結果」；機率 ≥ 0.5 時要求使用者確認 | Should | P2 |
| FR-304 | 確認等待超過 5 分鐘仍未回應，視同拒絕 | Should | P1 |
| FR-305 | 絕不輸入密碼：瀏覽器會攔截對 `input[type=password]` 的輸入，桌面模式則攔截模型自己標示為密碼的輸入，兩者都改為呼叫 `ask_user` | Must | P1 |
| FR-306 | 使用者可以設定網域封鎖清單，以及視窗封鎖清單（例如銀行、密碼管理器） | Should | P1 |
| FR-307 | 第一次對某個目標執行任務時，應顯示風險聲明，內容包括遊戲封號風險、免費版資料使用條款；使用者同意後記錄在知識庫中 | Must | P2 |

### 2.5 技能錄製與重播

| 編號 | 需求 | 等級 | 階段 |
|---|---|---|---|
| FR-401 | 任務成功後，使用者可以把整個任務「存成技能」並命名（P1，第 4 週已實作）；中途請使用者協助過的任務不能存。P2 再加上自動把連貫片段提議成多個技能 | Must | P1 |
| FR-402 | 技能的每一步應記錄：動作、參數、定位資訊（瀏覽器的 role/name/文字/CSS，或桌面的參考圖塊）、座標、執行前狀態、預期的結果狀態 | Must | P1 |
| FR-403 | 重播時，定位順序如下：瀏覽器是 role+name → 文字 → CSS → 座標；桌面是參考圖塊模板比對 → 座標。用座標之前，必須確認座標上的元素 role 與錄製時相同，否則視為找不到（避免版面改變後盲點） | Must | P1/P2 |
| FR-404 | 重播某一步失敗時，應從該步交給代理人迴圈接手（自我修復）；成功後產生技能的新版本 | Must | P1 |
| FR-405 | 代理人迴圈應提供 `use_skill(name)` 函式，讓 AI 主動呼叫已學會的技能 | Must | P2 |
| FR-406 | 技能應記錄成功與失敗次數；連續失敗 3 次就標記為「需要重新學習」 | Should | P2 |
| FR-407 | 瀏覽器技能可以匯出成獨立的 Playwright Python 腳本 | Could | P1 |

### 2.6 目標知識庫（不用改程式的關鍵）

| 編號 | 需求 | 等級 | 階段 |
|---|---|---|---|
| FR-501 | 第一次遇到新目標時，系統應自動建立一份空的知識庫，不需要使用者寫任何設定 | Must | P2 |
| FR-502 | 知識庫包含：目標資訊、操作模式、畫面狀態清單、技能清單、心得清單、使用者說明、自訂按鍵設定 | Must | P2 |
| FR-503 | 應提供 `register_state(name, description)` 函式；AI 認為目前畫面是值得記住的狀態時呼叫，系統保存目前截圖作為參考圖 | Must | P2 |
| FR-504 | 應提供 `save_note(text)` 函式，讓 AI 記錄學到的操作心得；同一目標的心得超過 50 條時，由 AI 整理合併 | Must | P2 |
| FR-505 | 每次任務開始時，應把該目標的使用者說明、心得、技能清單、狀態清單放進系統指示 | Must | P2 |
| FR-506 | 前端應能檢視與編輯知識庫：重新命名或刪除狀態、刪除技能、編輯心得、填寫使用者說明 | Should | P2 |
| FR-507 | 知識庫應可匯出成單一 zip 檔（JSON 加參考圖），也能匯入 | Should | P2 |
| FR-508 | 第一次使用某個目標時，可以用 Google 搜尋（grounding）查詢「這款遊戲的基本操作和每日任務」，整理成心得，並標記來源為 `web` | Could | P2 |
| FR-509 | 操作模式可以由使用者指定；未指定時預設為 `ui`，AI 也可以透過 `request_mode(realtime)` 建議切換，使用者同意後生效 | Should | P3 |

### 2.7 判斷層（Decisions API）

| 編號 | 需求 | 等級 | 階段 |
|---|---|---|---|
| FR-601 | 每一步開始前，若知識庫中已有 ≥ 2 個狀態，應以截圖向 Decisions API 提出 `choice` 問題（選項為所有已知狀態加上 `unknown`） | Must | P2 |
| FR-602 | 判斷結果的 `confidence` ≥ 門檻（預設 0.8），而且目前子目標有對應這個狀態的技能時，直接重播該技能，不呼叫代理人模型 | Must | P2 |
| FR-603 | 判斷為 `unknown` 或信心不足時，交給代理人迴圈；狀態判斷結果也一併提供給模型參考 | Must | P2 |
| FR-604 | 判斷結果（各選項機率、信心值）應寫入步驟紀錄 | Should | P2 |
| FR-605 | 代理人宣告完成前（呼叫 `task_done` 或直接用文字回答），用 `noul` 問題驗證「畫面是否顯示任務已完成」；機率低於門檻（預設 0.5）就退回給模型繼續做，退回 2 次後仍堅持完成則任務判定**失敗**，不謊報成功。Decisions 出錯時略過檢查。（2026-11-24 提前到 P1：遊戲試跑時模型只玩了幾步就謊報「完成第一關」） | Must | P1 |

### 2.7a Decisions 選候選（不呼叫代理人模型決定點哪裡）

依據：第 0 週 spike 04（[spike-report.md](spike-report.md) 2.4）。

| 編號 | 需求 | 等級 | 階段 |
|---|---|---|---|
| FR-650 | 判斷層沒有可用技能時，應先嘗試「Decisions 選候選」，失敗才交給代理人模型 | Must | P1（瀏覽器）／P2（桌面） |
| FR-651 | 候選來源：瀏覽器取 DOM 中可見、可互動的元素；桌面取 OCR 文字框與按鈕輪廓偵測結果。重疊的候選要合併，每次最多 60 個 | Must | P1／P2 |
| FR-652 | 應在截圖副本上為每個候選畫編號標記（Set-of-Mark），以 `choice` 問題提問；選項為各編號加上 `none`，問題內容包含目前的子目標 | Must | P1／P2 |
| FR-653 | 選中的不是 `none`，且 `confidence` ≥ 門檻（預設 0.8）時，點擊該候選的中心；否則改走 FR-654 或交給代理人模型 | Must | P1／P2 |
| FR-654 | 桌面畫面找不到任何候選時，使用兩段式格子定位（12×8 格，再放大附近區域用 6×6 格）。信心值以「選中格與相鄰格的機率加總」計算，門檻另外設定（預設 0.6） | Should | P2 |
| FR-655 | 以下情況不使用選候選，直接交給代理人模型：需要輸入文字、需要拖曳／按住／視角等非點擊動作、**上一步是第 3 層點的而且畫面沒有變化**（只看第 3 層自己的上一步：輸入文字這類小變化，差異雜湊常常偵測不到） | Must | P1／P2 |
| FR-656 | 同一張截圖的多個問題（畫面狀態、下一步選哪個候選、子目標是否已完成）應合併成一次請求，共用截圖的輸入 token | Must | P2 |
| FR-657 | 選中的候選在點擊前，仍要經過高風險檢查（FR-303）：只標出選中的那一個候選，再問一次 `noul` | Must | P1／P2 |
| FR-658 | 選候選的結果（選項、各選項機率、信心值、候選數量）應寫入步驟紀錄，`layer` 標記為 `actor` | Should | P1 |

### 2.8 桌面執行器

| 編號 | 需求 | 等級 | 階段 |
|---|---|---|---|
| FR-701 | 只擷取目標視窗的客戶區截圖；座標以客戶區為基準換算 | Must | P2 |
| FR-702 | 執行動作前，應確認目標視窗在前景；不在前景時嘗試帶到前景，失敗就暫停任務 | Must | P2 |
| FR-703 | 鍵盤輸入應使用掃描碼（SendInput），以相容 DirectInput 遊戲 | Must | P2 |
| FR-704 | 目標程式以系統管理員權限執行、但本程式沒有時，應提示使用者以系統管理員身分重新啟動 | Must | P2 |
| FR-705 | 緊急停止快捷鍵（預設 `Ctrl+Alt+Q`）應立即停止任務，並放開所有按鍵 | Must | P2 |
| FR-706 | 視窗大小或位置改變時，應自動重新計算座標基準 | Should | P2 |

### 2.9 即時模式

| 編號 | 需求 | 等級 | 階段 |
|---|---|---|---|
| FR-801 | 即時模式應提供以下動作：`hold_keys(keys, seconds)`（可同時按住多個鍵）、`look(dx, dy)`（相對滑鼠移動）、`hold_mouse(button, seconds)`、`tap_keys(keys)`、`look_and_hold(...)`（組合動作） | Must | P3 |
| FR-802 | 模型一次回傳 1–5 個動作，組成一個「動作區塊」，依序執行完畢後再截圖 | Must | P3 |
| FR-803 | 單一動作的持續時間上限為 5 秒，整個區塊上限為 10 秒 | Must | P3 |
| FR-804 | 目標設定了暫停鍵時（例如 Minecraft 的 `Esc`），啟用「思考時暫停」：截圖 → 按暫停 → 等模型回應 → 按恢復 → 執行動作區塊 | Should | P3 |
| FR-805 | `look` 的換算比例（像素對應的角度）應可校正：第一次使用時讓 AI 執行校正動作，把結果存入知識庫 | Should | P3 |
| FR-806 | 截圖時可以額外附上「動作區塊執行過程中」的 2–3 張縮圖，讓模型了解移動過程 | Could | P3 |

### 2.9a 反射層（2026-11-24 加入，P1 網頁遊戲先行）

代理人模型每步要 3–10 秒，來不及做「對齊敵人、攻擊、閃躲」這類即時反應。反射層把工作拆成兩層：代理人（慢）看懂遊戲後寫規則；Decisions（快，每輪約 1 秒）照規則看畫面選一條，程式立刻按鍵。規則是資料，換遊戲不用改程式。

| 編號 | 需求 | 等級 | 階段 |
|---|---|---|---|
| FR-670 | 遊戲模式提供 `set_reflex(question, rules, iterations)`：`rules` 2–12 條，每條有代號（英文小寫）、`when`（畫面情況描述）、動作（`hold`／`tap`／`wait`）、按鍵（最多 3 個）、秒數（≤2 秒）或次數（1–5 次）；`iterations` 1–60 輪。代號不得重複，`unknown` 保留 | Must | P1 |
| FR-671 | 每一輪：截圖 → 只裁出遊戲畫面（FR-401 的 focus 區域）並縮到長邊 512px → 以 `choice` 問題問 Decisions（選項為各規則加上 `unknown`）→ 立刻執行選中規則的按鍵。不呼叫代理人模型 | Must | P1 |
| FR-672 | 選中 `unknown` 或信心低於門檻（預設 0.5）時不按鍵；連續 3 輪如此，或遊戲畫面連續 6 輪沒有變化、按鍵失敗、Decisions 出錯或額度用完時，提前停止並交回代理人 | Must | P1 |
| FR-673 | 跑完後回報給代理人：輪數、按鍵次數、各規則次數、Decisions 平均延遲、停止原因、最後一輪的選擇；代理人再決定調整規則或改做別的 | Must | P1 |
| FR-674 | 每次按鍵記成一個步驟，`layer` 為 `reflex`、模型為 Decisions；這些步驟不計入代理人的步數上限，但仍受時間上限與「停止」控制 | Must | P1 |
| FR-675 | 反射層的按鍵仍經過安全檢查（FR-3xx）；停用反射層時 `set_reflex` 回傳錯誤，請模型改用 `hold_keys`／`tap_keys` | Must | P1 |
| FR-676 | 設定檔 `gemini.reflex`：`enabled`、`max_side`、`threshold`、`max_unknown`、`stall_ticks`、`max_iterations` | Must | P1 |

### 2.10 長任務規劃

## 4. 外部介面需求

### 4.1 Gemini Interactions API（代理人模型）

| 項目 | 規格 |
|---|---|
| SDK | `google-genai` ≥ 3.2 |
| 呼叫 | `client.interactions.create(model, input, tools, previous_interaction_id)` |
| `native_cu` 工具 | `{"type": "computer_use", "environment": "browser" \| "desktop", "enable_prompt_injection_detection": true}`，再加上自訂 `function` 工具 |
| `custom_fc` 工具 | 只有自訂 `function` 工具（動作集見 SDD 4.2） |
| 座標 | 正規化 1000×1000 |
| 模型 | 依退階鏈；**第 0 週要驗證**每個模型在免費版能不能用 `computer_use`、能不能用函式呼叫加上圖片輸入 |

### 4.2 Gemini Decisions API

| 項目 | 規格 |
|---|---|
| 呼叫 | `genai.Client(http_options={"api_version": "v1beta"}).decisions.create(model="gemini-decision-1", input, questions)` |
| 免費版配額 | 200 RPM、50,000 TPM、10,000 RPD；輸入免費 |
| 限制 | 不支援工具；每次 1–1000 題；輸入上限 262,144 token |

### 4.3 Google 搜尋 grounding（Could）

用於 FR-508，只在建立知識庫時呼叫一次，受配額管理控管。

### 4.4 Playwright

Chromium，`launch_persistent_context`，有視窗模式，預設 1280×800；在頁面內以 JS 收集可見、可互動元素，加上 `data-familiar-ref` 標記產生元素參照（第 2 週實作；比解析 ARIA 快照文字更容易取得邊界框）。輸入框的值一律不回傳，避免密碼或個資外洩給模型。

### 4.5 Windows

| 用途 | 套件／API |
|---|---|
| 列出視窗、取得客戶區、帶到前景、判斷權限 | `pywin32` |
| 視窗截圖 | `mss`（依客戶區座標）；畫面全黑時改用 Windows Graphics Capture |
| 鍵盤／滑鼠（含相對移動、按住） | `SendInput`，掃描碼與 `MOUSEEVENTF_MOVE`（用 `ctypes` 自行封裝，或使用 `pydirectinput`） |
| 緊急停止快捷鍵 | `keyboard` 全域熱鍵 |

### 4.6 前端 ↔ 後端

REST 加 WebSocket（詳見 SDD 5），只在本機使用，驗證用啟動時產生的 token。
