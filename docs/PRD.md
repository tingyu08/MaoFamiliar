## 1. 產品概述

### 1.1 背景

想交給電腦自動完成的事情有三類：

1. **網頁操作**：查資料、填表、在後台點來點去。每次要做的事不一樣。
2. **遊戲與應用程式的例行工作**：例如崩鐵國際服、妮姬的每日任務。
3. **讓 AI 自己玩遊戲**：例如 Minecraft 單人模式。目標比較開放，例如「去砍樹做一張工作台」。

現有工具的問題是**每款遊戲都要專門寫程式**。March7thAssistant 只支援崩鐵國服簡中客戶端；換一款遊戲，就要重做模板、重寫流程。

### 1.2 產品願景

**一個通用的 AI 電腦操作代理人：指定目標（網址或視窗）並用一句話描述要做的事，它就會自己看畫面、自己操作，而且越用越快。**

- **不用改程式**：新的遊戲或應用程式只要選擇視窗、描述目標就能開始，程式裡不寫任何遊戲專屬的邏輯。
- **自己學習**：AI 在操作過程中把學到的東西存成這個目標的**知識庫**，內容包括畫面狀態、可重複使用的技能、操作心得。下次遇到同樣的畫面，就直接走快速路徑。
- **自我修復**：遊戲或網站改版導致快速路徑失效時，交還 AI 接手並更新知識庫。
- **省額度**：只需要點擊的步驟，由配額充足的 Decisions API 從畫面上的候選中挑選；只有要打字、拖曳、規劃或卡住時，才動用額度很少的代理人模型。

### 1.3 產品目標

| 編號 | 目標 |
|---|---|
| G1 | 在前端輸入「網址＋想做的事」，AI 就用瀏覽器完成，過程可以即時觀看 |
| G2 | 在前端選擇「任一視窗＋想做的事」，AI 就操作該桌面應用程式或遊戲，**新增目標不需改程式** |
| G3 | 每個目標自動建立知識庫；同一件事做第二次時，AI 呼叫次數明顯減少 |
| G4 | 支援即時遊戲的基本操作，例如按住按鍵移動、轉動視角、長按挖掘，以 Minecraft 單人模式為驗收範例 |
| G5 | **只用 Gemini 免費額度**：自動追蹤配額，額度用完時依序退回較舊的模型 |
| G6 | 高風險動作一律暫停，等使用者確認 |

## 2. 目標使用者與使用情境

### 2.1 使用者

**開發者本人（單人使用）。** 在 Windows 11 上使用，有程式背景，會自行設定 API key。不需要多人帳號。

### 2.2 使用情境

| 編號 | 情境 | 期望結果 |
|---|---|---|
| UC1 | 輸入網址和「找到最新公告，告訴我標題和日期」 | AI 在瀏覽器中操作，最後回報答案 |
| UC2 | 第一次對崩鐵國際服說「完成今天的每日實訓」 | AI 自己摸索完成；過程中學到的畫面和技能存入「崩鐵」知識庫 |
| UC3 | 隔天再說一次同樣的話 | 大部分步驟走快速路徑，AI 呼叫次數比第一次少 50% 以上 |
| UC4 | 遊戲改版後，介面按鈕換了位置 | 快速路徑失敗的步驟交還 AI 處理，知識庫自動更新 |
| UC5 | 開啟一款從沒用過的遊戲，說「完成新手教學」 | 不用改任何程式，選好視窗就能開始 |
| UC6 | 在 Minecraft 單人模式說「砍一棵樹，做出工作台」 | AI 用按住 W、轉視角、長按左鍵等動作完成；思考時自動暫停遊戲 |
| UC7 | AI 準備按下「購買」或「送出」 | 前端跳出確認窗，使用者同意才執行 |
| UC8 | 今天某個模型的免費額度用完，或一直回 503 過載 | 該工作的退階鏈自動換下一個模型（操作：3.5 Flash-Lite → 3.6 Flash → 3.8 Flash；規劃：Hydrogen → 3.8 Flash → 3.6 Flash → 3.5 Flash-Lite）；全部用完時暫停，等太平洋時間午夜額度重置 |
| UC10 | 每天早上 6 點自動跑崩鐵每日任務 | 排程啟動，結束後推播結果 |

## 3. 能力邊界

**這是最重要的一節。** AI 每一步都要「截圖 → 送給 Gemini → 等回應」，一步大約 2 到 10 秒。所以能做到什麼，取決於遊戲需要多快的反應。

| 遊戲類型 | 例子 | 預期效果 | 支援 |
|---|---|---|---|
| 選單式／回合制 | 手遊日常、崩鐵、卡牌、策略遊戲 | **好**：畫面停著等你操作，延遲不影響結果 | ✅ 主要目標 |
| 慢節奏即時、可暫停 | Minecraft 單人（和平或簡單難度）、模擬經營、農場遊戲 | **可用但笨拙**：能完成簡單目標，但動作不流暢、會走錯路 | ✅ 即時模式（P3） |
| 快節奏即時 | 動作遊戲、Minecraft 打怪、平台跳躍 | **差**：反應太慢，常常失敗 | ⚠️ 不保證 |
| 多人競技／有核心層反作弊 | FPS、MOBA、排位賽 | 不可行，而且有封號風險 | ❌ 非目標 |

**免費額度的限制（第 0 週驗證）**：每一步實測要 3 到 35 秒；代理人模型每天合計大約只有幾十到一百步可用（Hydrogen 與 3.6 Flash 各 20 次）。選單式遊戲靠技能重播和 Decisions API 分擔仍然可行；**即時模式在免費版只能做很短的實驗**，例如砍一棵樹就可能用掉一整天的額度。

## 4. 功能範圍

### 4.1 階段規劃

| 階段 | 名稱 | 內容 |
|---|---|---|
| **P1** | 核心＋網頁代理人（MVP） | 代理人迴圈、模型與配額管理、Playwright 執行器、安全確認、錄製重播、前端 |
| **P2** | 通用桌面代理人＋知識庫 | 任一視窗的截圖與輸入（UI 模式）、自動學習的目標知識庫、Decisions API 判斷畫面、長任務規劃 |
| **P3** | 即時模式 | 按住按鍵、相對滑鼠視角、動作區塊、思考時暫停遊戲；以 Minecraft 單人驗收 |
| **P4** | 排程與通知 | 定時執行、推播 |

### 4.2 功能清單

| 編號 | 功能 | 階段 | 優先級 |
|---|---|---|---|
| F1 | 輸入網址或選擇視窗，再加上任務描述，就能開始任務 | P1/P2 | Must |
| F2 | 即時畫面、步驟紀錄、AI 說明、配額與模型顯示 | P1 | Must |
| F3 | 隨時停止任務；桌面模式另有緊急停止快捷鍵 | P1/P2 | Must |
| F4 | 高風險動作的確認窗 | P1 | Must |
| F5 | AI 主動請使用者協助（登入、驗證碼、資訊不足） | P1 | Must |
| F6 | 模型退階鏈與每日配額追蹤 | P1 | Must |
| F7 | 錄製成功的操作，可以重播並自我修復 | P1 | Must |
| F8 | 選擇任一視窗作為目標（不用寫程式） | P2 | Must |
| F9 | 目標知識庫：自動學習畫面狀態、技能、操作心得 | P2 | Must |
| F10 | 知識庫可在前端檢視、編輯、刪除、匯出、匯入 | P2 | Should |
| F11 | 使用者可以替目標補充說明，例如「按 E 開背包」 | P2 | Must |
| F12 | 長任務自動拆解成子目標並追蹤進度 | P2 | Should |
| F13 | 第一次使用某個目標時，用 Google 搜尋整理操作說明 | P2 | Could |
| F14 | 即時模式：按住按鍵、組合鍵、相對滑鼠、長按滑鼠 | P3 | Must |
| F15 | 思考時自動暫停遊戲，暫停鍵由使用者設定 | P3 | Should |
| F16 | 排程與推播 | P4 | Should |
| F18 | 只需要點擊的步驟，由 Decisions API 從畫面候選中選出下一步，不消耗代理人模型的額度 | P1（網頁）／P2（桌面） | Must |

### 4.3 非目標

- **核心程式不寫任何遊戲專屬邏輯**，所有遊戲知識都是資料。
- 不做多人帳號、雲端執行桌面操作（桌面操作一定在使用者自己的電腦上）。
- 不破解驗證碼、不繞過反作弊、不讀寫遊戲記憶體、不修改封包。
- 不儲存、不輸入使用者的密碼。
- 不支援多人競技遊戲。

## 5. 成功指標

| 指標 | 目標值 |
|---|---|
| 新增一個目標（遊戲或應用程式）需要修改的程式碼 | **0 行** |
| 簡單網頁任務（≤ 15 步）的成功率 | ≥ 80% |
| 選單式遊戲的每日任務：第二次執行時，AI 呼叫次數比第一次減少 | ≥ 50% |
| 錄製的技能重播成功率（目標未改版時） | ≥ 95% |
| Minecraft 單人：「砍樹並做出工作台」在 60 步內的成功率 | ≥ 50%（探索性指標） |
| 費用 | US$0（只用免費額度） |
| 高風險動作未經確認就執行 | 0 次 |

## 6. 風險

| 風險 | 影響 | 機率 | 對策 |
|---|---|---|---|
| **Computer Use 工具可能不在免費額度內**：價格頁的工具表顯示免費版「Not available」，這一點尚未完全確認 | 高 | 中 | 設計兩種動作後端：原生 Computer Use 與**自訂函式呼叫**。自訂函式呼叫用一般模型讀截圖、輸出座標，免費版可以使用（見 SDD 4.2） |
| 免費配額太少，一款遊戲的日常可能就用光當天額度 | 高 | 高 | 知識庫與快速路徑減少呼叫次數、模型退階鏈；Decisions API 免費版每天有 10,000 次，優先用它判斷畫面 |
| **免費版的輸入內容會被 Google 用來改善產品**，截圖可能包含個人資訊 | 中 | 確定 | 只擷取目標視窗；啟動時顯示說明；建議執行時關閉敏感視窗 |
| 即時遊戲反應太慢 | 中 | 高 | 動作區塊、思考時暫停；在文件中說清楚能力邊界（第 3 節） |
| 遊戲封號（崩鐵的公平遊戲聲明、妮姬的 ACE 反作弊都禁止自動化） | 高 | 中 | 第一次對某個目標使用時顯示風險聲明；預設不支援多人競技 |
| AI 誤操作（點錯、送出不該送的東西） | 中 | 中 | 確認窗、步數上限、緊急停止 |
| 網頁或遊戲畫面裡的文字試圖誘導 AI（提示注入） | 中 | 中 | 支援時開啟偵測；任務描述只來自使用者輸入；高風險動作必須確認 |
| Gemini 模型 ID 或 API 變動 | 中 | 中 | 模型清單放在設定檔；API 呼叫集中在一個封裝層 |

## 7. 決策紀錄

v0.1 待決事項的答案：

| 編號 | 問題 | 決定 | 對設計的影響 |
|---|---|---|---|
| Q1 | 崩鐵玩國服還是國際服？ | 國際服 | 不整合 March7thAssistant，崩鐵也走通用代理人 |
| Q2 | 是否需要手機或遠端查看？ | 原本考慮放到 Vercel，2026-11-23 改為**前端也在本機執行** | 前端由後端在 `127.0.0.1` 直接提供，不做遠端連線 |
| Q3 | Gemini 每月費用上限？ | 只用免費額度 | 新增配額管理（F6）；動作後端要能在沒有 Computer Use 的情況下運作 |
| Q4 | 用哪個模型？ | 先用 `gemini-4-hydrogen`，額度不夠退到 `gemini-3.8-flash`，再不夠退到 `gemini-3.6-flash`，3.6 Flash 也沒額度或出錯時退到 `gemini-3.5-flash-lite`（2026-11-23 追加）。驗證後改為**依工作分工**（見 Q8） | 模型退階鏈寫進設定檔；額度用完與錯誤都會觸發退階 |
| Q5 | 支援哪些遊戲？ | 不限，未來新增遊戲不用改程式（例如 Minecraft 單人） | 產品改成通用代理人＋知識庫；新增即時模式 |
| Q6 | 原生 Computer Use 與自訂函式要用哪個？ | 第 0 週驗證：原生的免費版可以用，但會隨機被安全分類器擋下；**預設用自訂函式**，原生保留為選項 | SRS FR-101、FR-101a |
| Q8 | 模型怎麼分配？ | **依工作分工**（2026-11-23）：操作用 3.5 Flash-Lite → 3.6 Flash → 3.8 Flash；規劃用 Hydrogen → 3.8 Flash → 3.6 Flash → 3.5 Flash-Lite；判斷用 Decisions API | SRS FR-201、SDD 4.4 |
| Q7 | 是否接受免費版截圖會被 Google 用來改善產品？ | **接受**（2026-11-23） | 維持免費版；仍只擷取目標視窗，並在啟動時提示（NFR-205、NFR-206） |
